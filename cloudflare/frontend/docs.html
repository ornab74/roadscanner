COMPLETE ROUTE INTEGRATION

From API key to mapped route.

Run the full server-side workflow: account check, route creation, directions, section risk, GeoJSON and saved-report retrieval.

  1. 1. Create your account & keyIn Settings → API access, create an expiring Road planner key. This workflow needs account:read, routes:write, scans:read, and operations:read.
  2. 2. Prepare your serverUse a private working directory and install the selected language dependencies shown in the example. Store your key as QRS_API_KEY in the server environment. Never put it in a public browser bundle.
  3. 3. Choose endpoints & vehicleThe example uses public, mapped Fifth Avenue road points. To use addresses, resolve and confirm the right candidate first. Optionally supply an owned garage vehicle_id.
  4. 4. Run & inspectThe script saves route-response.json and, for accepted routes, route.geojson. Read the turn instructions, modeled section scores, coverage and endpoint offsets.
  5. 5. Recover without duplicate workKeep qrs-operation.json. After a timeout, rerun the same body and idempotency key. On a pending 409, wait; use operation status when its ID is known.
