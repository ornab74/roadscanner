# Endpoint and connector review

The route alignment previously considered only the nearest road edge at each endpoint. A disconnected parking/service feature could reject the route before considering a nearby mapped connection. The revised matcher keeps the nearest projection on each road feature, tries the original nearest pair first, then performs one bounded multi-anchor directed search only when that pair cannot connect.

Each endpoint has at most eight candidates within the existing 150 m offset limit and no more than 30 m farther away than its nearest feature. A single feature cannot offer progressively displaced projections to evade a one-way restriction. One-way rules, feature/geometry/search budgets, detour checks, corridor checks, and junction snapping remain enforced. No off-road line is drawn between a pin and the mapped approach. Selected offsets and whether alternatives were used are reported in `geometry_alignment.endpoint_matching`; actual entrance access remains unverified.

Map imports now choose the finest tile coverage allowed by the provider's advertised maximum zoom and the existing 36-tile budget. OpenFreeMap currently advertises zoom 14, so the adapter never requests unsupported zoom 15/16 tiles, which can return empty data. Longer trips retain bounded coarser coverage. An offline replay of the latest completed journey against live higher-detail tiles reduced its start offset from approximately 128 m to 41 m and identified additional street names. This does not establish that every failed historical request used identical endpoints; failed raw images and inputs are not retained.

The automatic atlas retains broad endpoint/network views and adds tighter labeled street and aerial endpoint views. Once mapped geometry exists, up to two distinct connector junctions (first and last endpoint approaches prioritized) receive street/aerial close-ups. The final mapped review receives the images plus geographic bounds and section IDs, rather than text facts alone. Image origins, formats, dimensions, byte limits and redirects remain validated; missing imagery is reported rather than fabricated. Provider resolution and service availability can limit close-up coverage.

Turn headings retain meaningful short entrance directions while stabilizing sub-3 m leading/trailing edge noise over a short approach. The model is instructed to compare straight-through versus side-entrance evidence and not invent a U-turn from a tiny snapped edge, earlier hypothesis or remembered store layout. Neither route geometry nor aerial imagery verifies signs, lane permission, legal access, or current conditions.

The dashboard provides **Inspect start entrance** and **Inspect destination entrance** controls that zoom to level 19 without entering map-click placement mode. These controls do not spend credits or automatically move an already selected endpoint. Users can inspect/drag the existing pin to the actual driveway, then generate a fresh proposal; stored historical reports are not rewritten. The controls are unavailable while planning/comparison is in flight.

For close aerial exports that fail (including zero-sized provider metadata), the capture stage can use two neighboring native World Imagery tiles at zoom 19. It retains the same fixed HTTPS provider, redirect rejection, image-format/dimension checks, response-byte limits, and explicit per-tile geographic bounds. The result warns that coverage is partial. Final review accepts at most 12 image frames, enough for bounded endpoint and first/last connector evidence; it does not treat satellite images as verified signs or turn legality. Live native-tile capture was checked without making AI calls or consuming account credits.

A read-only comparison using identical nearby endpoint cases and live map data reproduced seven prior no-connection failures with the old coarse source; all seven connected using the finer bounded source and updated endpoint handling. This is a regression check of map geometry, not verification of an entrance turn or a new AI navigation result. The final full suite passed 174 tests, and desktop/mobile entrance controls were checked in the isolated browser fixture.
