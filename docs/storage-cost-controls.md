# Storage and compute cost controls

The application reports bucket has a 1 GiB (1,073,741,824-byte) logical payload cap and a 10,000-object cap. This is an application write guard, **not a Cloudflare account storage limit or a guaranteed maximum bill**. It excludes D1, container disk, registry images, other buckets, R2 operation charges, metadata overhead and external AI providers.

`cloudflare/report-storage.mjs` guards all request and scheduled-event access to `REPORTS`. Before an immutable object write, a D1 trigger atomically reserves its exact UTF-8/binary payload bytes. Concurrent puts cannot exceed the recorded budget. Payloads must have a known size and cannot exceed 8 MiB. Duplicate keys cannot overwrite tracked data. New analysis/image requests check available capacity before charging or contacting providers; the final atomic allocation remains authoritative if requests race.

Reads and replays remain available at capacity. Cleanup releases bytes only after an R2 deletion succeeds. Existing cleanup/retention rules continue; the cap itself does not delete old reports or shorten retention. An uncertain put retains its reservation because R2 might have accepted it. This deliberately overcounts until an operator reconciles the failed write against authoritative R2 metadata. Do not release a pending reservation until the writer is definitively finished and the object outcome is known.

Migration 0016 begins uninitialized and blocks guarded writes. Deployment must briefly pause new inference work, drain existing reservations, inventory all existing R2 objects, seed the accounting ledger and mark it initialized, deploy the guarded Worker, and restore the prior pause setting. Existing objects count toward the cap; even data already above the cap is preserved. Initialization and the pause changes are audited.

Admin → Storage limit displays reserved bytes and object count after recent identity verification. `/api/admin/storage` is cookie-session, elevated-admin-only and does not expose object names or payloads. Caps are deliberately not editable through the public/admin API. Change the reviewed database configuration if a new capacity is explicitly authorized.

Direct S3, REST, dashboard or another Worker's writes bypass this application guard. Keep the bucket private and route application writes through the guard. An external writer requires a controlled pause and reconciliation before relying on the accounting again. Database state is trusted operational data: changing or deleting its ledger manually can break the guard. Do not restore D1 independently of the bucket without reconciliation. Cloudflare storage metrics may lag and do not replace this atomic write admission control.

As of November 14, 2026, separate native account limits are enabled for Workers usage ($10) and Durable Objects usage ($5). The base Workers subscription is $5. These are not a combined $25 invoice cap: metering/enforcement lag, Containers, D1, R2, stored data, and other products remain outside those product limits. See https://developers.cloudflare.com/billing/manage/spend-management/.

The private scanner starts a `standard-1` instance (0.5 vCPU, 4 GiB memory, 8 GB disk), with outbound Internet disabled and a five-minute inactivity timeout. Normal scans use the shared `roadscanner-singleton` Durable Object. Instance count alone does not bound monthly charges: runtime matters. At published rates, two 4 GiB containers running for 720 hours would cost about $51.84 in memory before included usage, plus CPU and disk. A simulated workload still incurs actual compute charges. No new container runtime budget or D1 physical-size cap is claimed by this change.

Production sets `LOCAL_SCANNER_ENABLED=false`. The scene API rejects explicit `llama_local` requests before provider work or credit reservation, defaults new scene requests to OpenAI when a model is omitted, and excludes local inference from the model catalog. The private bridge also refuses to start a container while disabled. Existing legacy reports remain readable. The deployment definition/model image is retained for rollback, but disabling does not delete stored data or images. Already-running instances can finish and sleep under their existing inactivity timeout. Tests explicitly enable the local fixture when exercising legacy functionality.
